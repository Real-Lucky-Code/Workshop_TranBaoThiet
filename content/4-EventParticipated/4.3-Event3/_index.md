# Harvest Report: "GameDay - 8 Teams Competing for Glory"

### Purpose of the Event

- Create a playground to help participants consolidate and test their knowledge of **Amazon Web Services (AWS)** through questions and real-world scenarios.
- Practice the ability to analyze requirements and select appropriate AWS services to solve Cloud architecture problems.
- Enhance teamwork skills, critical thinking, and decision-making capabilities in a time-constrained environment.
- Create opportunities for networking, learning, and sharing experiences among students participating in the **First Cloud Journey** program.

### Event Information

- **Event name:** GameDay - 8 Teams Competing for Glory.
- **Program series:** First Cloud Journey.
- **Time:** June 20, 2026.
- **Format:** Team-based competition with multiple-choice questions and real-world scenarios related to AWS services and architecture.
- **Participants:** Students and competing teams belonging to the First Cloud Journey program.

### Competition Format

GameDay was organized as a team-based competition through the **Live Match Control** system, allowing real-time updates of the leaderboard (**Team Scoreboard**) and questions. Teams would coordinate to analyze requirements, choose appropriate answers, and compete directly with one another throughout the duration of the contest.

Some highlights of the competition:

- Questions were divided into various score levels such as **10 points**, **50 points**, **100 points**, etc., depending on the difficulty.
- Teams could choose the **Minimum Risk** mode to reduce risk or use the **Hope Star** to increase points when confident in their answers.
- Scores were continuously updated on the leaderboard, creating a lively and highly competitive tournament atmosphere.
- Teams not only needed to answer correctly but also had to choose appropriate strategies to maximize their scores.

### Key Highlights

The questions in GameDay were built based on real-world system deployment scenarios on AWS. Participants not only needed to memorize the function of each service but also had to analyze requirements, evaluate multiple options, and choose the most suitable solution based on criteria such as performance, security, scalability, and cost.

#### Security and Access Management on AWS

Questions focused on building security systems and controlling access permissions for applications on AWS.

- Using **AWS WAF** with **Rate-based Rules** to block anomalous requests and mitigate the risk of website attacks.
- Managing data access permissions on **Amazon S3** through **Bucket Policies** to ensure only authorized entities can access resources.
- Learning about **AWS Artifact** to check AWS compliance reports and security certifications for auditing and compliance requirements.

#### Serverless and Automated Data Processing

Several questions introduced how to build systems leaning toward **Serverless** and **Event-driven Architecture** to reduce operational costs and increase scalability.

- Combining **Amazon DynamoDB Streams** with **AWS Lambda** to automatically process data when changes occur in the database.
- Understanding how to build event-driven processing workflows helps reduce manual operations and enhance operational efficiency.
- Identifying appropriate cases to apply Serverless architecture in practice.

#### Hybrid Cloud and Data Storage

Questions required choosing appropriate storage solutions to optimize efficiency and cost.

- Using **AWS Storage Gateway (File Gateway)** to connect on-premises storage systems with AWS.
- Storing long-term data with **Amazon S3 Glacier** to reduce costs while still ensuring retrieval capabilities when necessary.
- Understanding how to deploy a **Hybrid Cloud** model to combine On-premises infrastructure with the Cloud environment.

#### Databases on AWS

The competition also addressed selecting appropriate databases for each type of application.

- Using **Amazon DynamoDB** for applications requiring high performance, flexible scalability, and NoSQL data management.
- Understanding the advantages of managed databases (Managed Databases) compared to self-deploying and operating them.
- Knowing how to choose the right database based on the characteristics of each problem.

#### Performance and Scalability

Questions helped participants understand how to build systems with flexible scalability that can handle large amounts of traffic.

- Using **Auto Scaling** to automatically adjust the number of resources according to actual traffic.
- Selecting an **Application Load Balancer (ALB)** to support **Path-based Routing**, **Host-based Routing**, and **WebSocket**.
- Designing systems with High Availability and Scalability to meet usage demands.

#### Cost Optimization and AWS Architecture

In addition to technical knowledge, GameDay focused on cost optimization and building efficient Cloud architectures.

- Using the **AWS Pricing Calculator** to estimate deployment costs before putting the system into operation.
- Applying the **AWS Well-Architected Framework**, especially the **Performance Efficiency** pillar, to choose the right type of resource for each need.
- Evaluating multiple design options to balance performance, security, scalability, and operational costs.
- Understanding that each problem can have multiple different solutions, and the choice always depends on the actual requirements of the system.

### What I Learned

#### Knowledge of AWS Services

Through the questions and real-world scenarios in GameDay, I had the opportunity to consolidate and expand my knowledge of many important AWS services.

- Better understanding how to use **AWS WAF** to protect applications against common attacks and control incoming traffic.
- Grasping how to manage access permissions to **Amazon S3** via **Bucket Policies** to ensure data security.
- Understanding how to combine **Amazon DynamoDB Streams** with **AWS Lambda** to build automated data processing workflows following the Event-driven model.
- Consolidating knowledge of **Amazon DynamoDB**, **Amazon S3 Glacier**, **AWS Storage Gateway**, **Application Load Balancer**, **Auto Scaling**, **AWS Artifact**, and the **AWS Pricing Calculator**.
- Clearly understanding the role of each service in building a Cloud system with scalability, high availability, and cost optimization.

#### Knowledge of Cloud Architecture

Besides learning about individual services, GameDay helped me better understand how to combine AWS services to build a complete architecture.

- Understanding how to deploy a **Hybrid Cloud** model by combining On-premises infrastructure with services on AWS.
- Grasping how to design systems with scalability, high availability, and good fault tolerance.
- Understanding the benefits of **Serverless** and **Event-driven** architectures in automating data processing workflows.
- Knowing how to evaluate multiple different deployment options based on criteria such as performance, security, scalability, and cost.

#### System Design Thinking

One of the most valuable things I learned after GameDay was the approach to solving an architectural problem on AWS.

- There is no single service or architecture that is the best for every case; rather, choices must be made based on the actual requirements of the system.
- Every design decision requires a trade-off between performance, cost, security, scalability, and availability.
- Understanding the nature of each service is more important than just memorizing its name or function.

- Practicing the ability to analyze requirements and select appropriate solutions for each situation.
- Improving logical thinking and problem-solving skills within limited time.
- Enhancing teamwork skills, exchanging ideas, and reaching a consensus on solutions with team members.
- Learning to make decisions based on multiple criteria instead of focusing on a single factor.
